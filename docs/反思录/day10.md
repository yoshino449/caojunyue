## 反思

1. **LLM 的上限由上下文决定，不由模型决定**：用户问"明天上午还有投影仪吗"得"暂无记录"、"哪天能约"得"无法判断"——不是模型不会推理，而是上下文只喂了"已预约记录"、缺"全部器材/全部时段"全集，做不了差集。补上全集 + 在 prompt 里写明"没出现在列表 = 可用""禁止说无法判断"后，同一模型就能算出可用时段。教训：增强 LLM 先看它"看得见什么"，而不是急着换模型或堆规则。

2. **可选登录靠"动手前先定边界"省掉返工**：登录系统按"可选登录 + 明文存储 + 前端存用户名"落地——不引入 token/session、不强制登录、预约时自动填当前用户名。动手前用三问把"登录与预约的关系 / 密码怎么存 / 登录态怎么维护"定死，避免了"改着改着加成完整鉴权"的返工。明确不做：token、加密、注册。

3. **演示数据要分两层：不为空，还要有分布**：3 条数据能让卡片不空，但统计图表只有 3 根柱子，看不出分布。批量写到 159 条（器材近均衡、跨两个月）后，柱状图与饼图一眼可读。教训：演示数据准备 = "不为空"（防"暂无数据"）+ "有分布"（撑起可视化）。

4. **路演 PPT 是讲故事，不是贴代码注释**：初版把 localStorage / `UNIQUE(equip_id,date,slot)` / 409 / `onRequestDelete` 直接搬进页面，评委看不懂。三轮迭代把术语翻译成场景——标题改成"换个设备就撞单？"、末页收束为"5 个坑 5 个闭环"。教训：路演的唯一问题是"它解决了谁的什么问题，现场真的能跑"，术语让位给场景。
