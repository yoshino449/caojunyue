## 反思

1. **测试脚本也是代码，红灯先查证据链**：T12 第一轮 5 组用例红了 4 组，差点去查 db.js 的 DELETE 语句，实际是 PowerShell 管道取 id 时发生成员枚举，`$id` 变成数组拼出 `/api/bookings/1 2 5 6 7 8 11`。「拿到 id=1 2 5 6 7 8 11」这行异常输出已经直接说出病因，忽略它去查接口就南辕北辙——异常输出就是线索；
2. **平台 API 命名约定必须逐字核对**：`onDelete` 和 `onRequestDelete` 差一个 `Request` 前缀，Cloudflare Pages Functions 不会报错提示，只会静默 405。这类 bug 静态检查、本地 `npm start` 都看不出来（本地走 backend/server.js 不受命名约束），只能靠线上实测；
3. **验收要覆盖写操作**：此前线上验收只测了 GET 接口和页面渲染，POST/DELETE 没实测，导致这个 405 bug 从 T2 上线一直潜伏到 Day3 走查才暴露——GET 通不代表写操作通；
4. **闭环走查要趁早**：「约→撞→取消→再约」这种端到端用例应该上线当天就跑一遍，而不是等到验收前。越早暴露，修复成本越低（这次只改一行，但如果拖到演示前才发现，慌乱中容易改错）。
