## 反思

### 1. 架构图让 AI 按代码画、人审——可行但需补虚线

让 AI 读 backend/functions/frontend 源码后画 Mermaid 架构图，初版准确反映了双轨架构（本地 backend+SQLite / 线上 functions+D1）和 CI 流水线三个子图。但 AI 初版漏画了"同代码/接口对齐/SQL 同构"三条虚线关系——这些跨子图的关联关系需要人审才能发现。结论：AI 画图在"组件+连线"层面可靠，但在"跨域语义关联"层面仍需人工补充。

### 2. 演示脚本 vs 实际走查：seed 占坑的教训

演示脚本写了「约→撞→取消→再约」4 步，但浏览器实际走查时发现 seed 数据已预置了一条投影仪预约占住了目标时段，导致步骤 1 直接撞单。这说明演示脚本不能只写 happy path，必须包含"前置准备：先取消 seed 预约释放时段"步骤。教训：演示脚本的"前置准备"不是可选项，是必须项——否则演示现场第一步就卡。

### 3. 整改闭环补做：402 状态码映射不一致

IKKO7A issue 正文为空，采用方案③自查评审补全。自查发现 functions/api/bookings/index.js 对 DeepSeek 402 返回 503，但本地 ai.js 映射 QUOTA→429——同一错误线上/线下状态码不一致。这类"本地能跑线上不对"的 bug 只有跨环境审查才暴露，说明仅本地测试（npm test 5/5 通过）不能覆盖部署适配层的逻辑差异。建议后续对 functions/ 子树做与 backend/ 的接口契约对齐测试。

### 4. MCP 配置最后一公里：Trae 保护文件限制

SQLite MCP 配置写入 ~/.trae-cn/mcp.json 成功，但项目级 .trae/mcp.json 被 Trae 标记为"模型不可写"（Access denied）。MCP 提效的配置文件可以由 AI 生成内容，但实际写入仍需人工在 Trae UI 中操作或手动放置。这说明 MCP 提效链路的最后一公里（写入受限路径、确认连接状态）仍需人工介入，AI 只能完成到"生成配置 JSON + 指导放置路径"。

## 待改进

1. **架构图应与代码同步**：目前 Mermaid 架构图是手写按代码画的快照，后续代码变更（如新增 API 路由、改 D1 binding）需人工同步更新图，容易遗漏。建议在 AGENTS.md 改动纪律中加"改路由→更架构图"检查项，与"接口变更必须同步 README API 表"并列。
2. **演示脚本应包含异常路径**：当前只走 happy path（约→撞→取消→再约），未演示 AI 助手失败兜底（503/504/429）。建议补一条"AI 断网→兜底提示"演示分支，让评委看到失败场景也有合理提示，而非只展示成功路径。
