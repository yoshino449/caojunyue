# 对话档案：部署手册留了占位符，写操作验收才算部署成功

> 本文档基于 Day4 反思件还原。

- 日期：2026-10-09
- 场景：Day4 部署手册补全上线信息并入库 + 上线后端到端全量验收
- 对话结构：提问 → 排查返工（3 轮）→ 通过

## 一、提问（原话）

> 部署手册补全上线信息并入库；上线后端到端全量验收。

## 二、对话还原

### 第 1 轮：AI 生成部署手册，配置块里留了占位符

**我**：把部署手册整理好，交给下届同学照着一步步做。

**AI**：生成手册初版，含 Cloudflare 主流程、验收 URL 清单与配置片段。但配置代码块里 `database_id` 仍写成 `"<部署后回填>"` 这类占位符，没有换成本项目实际值。

> 返工点：占位符留在最终配置代码块里，下届同学照抄会直接部署失败——占位符只该出现在「你需要替换的值」说明里。

### 第 2 轮：回填实例值 + 标注哪些要换

**我**：手册要能「照做即通」，把本项目的实际值填进去。

**AI**：回填本项目上线信息——线上域名 `https://caojunyue.pages.dev/`、D1 database_id `7f76097a-2ced-418c-8862-1d7cb99767cd`、5 个验收 URL，并把首次部署踩的坑整理成 3 条实录（commit `c1aac49`、`a63b25e`）。

随后补一段「哪些值要换成你自己的」提示（commit `febd846`）：`cao-junyue`、`yoshino449`、`caojunyue.pages.dev`、`7f76097a...` 都是本项目作者实例值，下届必须替换；唯一不用换的是数据库名 `equipment-booking` 与 binding 名 `DB`。

> 返工点：手册从「教程」变成「可复现指南」的关键，就是回填实例值。

### 第 3 轮：GET 全通不算数，补写操作闭环

**我**：5 个 URL 都返回正常，是不是就算部署成功了？

**AI**：GET 接口全通不代表部署成功——POST/DELETE 才是真实业务链路。于是补做写操作实测：POST 新建、DELETE 取消，验证 Day3 修复的 405 已生效。

> 返工点：端到端验收清单必须包含「约→撞→取消→再约」完整闭环，而不是只 curl 几个 GET。

## 三、通过证据

- 首页 `/`：三张卡片 + 页脚访问计数；`/ping` 返回 `ok`；`/api/ping` 返回 `ok`；
- `/api/bookings`：seed 2 条 JSON；`/api/visits`：`{"count":N}`；
- POST/DELETE 写操作实测通过（Day3 的 405 修复已生效）；
- commit：`c1aac49`、`a63b25e`（首次部署踩坑实录）、`febd846`（占位符替换提示）；
- tag `day4` 已推，「第 4 天完工报告」issue 已发。

## 四、反思

1. **部署手册不能留占位符交差**：占位符只该出现在「你需要替换的值」说明里，不该出现在最终配置代码块里；
2. **上线后端到端验收要覆盖写操作**：GET 全通 ≠ 部署成功，POST/DELETE 才是真实链路；
3. **部署选型要提前备 Plan B**：Sealos → Render → Cloudflare 换了三条路线才落地，选型阶段就要摸清每条路线的硬约束；
4. **双 remote 同步是纪律**：Cloudflare 只接 GitHub、Gitee 是主仓库，`git push origin main` → `git push github main` 缺一不可。
