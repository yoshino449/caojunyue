# 对话档案：三张卡片全显示「近期预约（0）」，前端过滤吃掉演示数据

> 本文档基于 Day9 反思件还原。

- 日期：2026-10-12
- 场景：Day9 T1 收尾冲刺（缺陷清零 + 演示数据准备）+ T2 彩排（个人路演 PPT / 草稿）
- 对话结构：提问 → 排查返工（3 轮）→ 通过

## 一、提问（原话）

> T1 收尾冲刺（缺陷清零 + 四件套入库 + 演示数据准备）+ T2 彩排（个人路演 PPT/草稿）。

## 二、对话还原

### 第 1 轮：API 有数据，页面却是「暂无数据」

**我**：演示数据准备好了吗？

**AI**：线上 D1 有 2 条 seed 预约（日期 10-09 / 10-10），API 返回非空，看起来没问题。

但走前端渲染确认后发现——前端 `b.date >= todayStr()` 过滤把过去日期全部滤掉，**三张卡片全部显示「近期预约（0）」**，评委第一眼就是「暂无数据」。

> 返工点：演示数据准备不能只看 API 非空，必须走前端渲染确认；前端过滤会让「API 有数据」和「页面有数据」脱节。

### 第 2 轮：POST 今天/未来预约，按评委视角复核

**我**：让每张卡片至少有一条能看到的预约。

**AI**：POST 3 条今天/未来的预约（三个器材各占 1 条），每张卡片各显示 1 条能看到的预约，评委视角正常。

> 返工点：演示数据的判定标准是「评委在页面上能看到」，不是「数据库里有」。

### 第 3 轮：路演 PPT 的选型——内容密度 vs 视觉炫技

**我**：3 分钟路演要一份 PPT。

**AI**：有两个选择——`html-deck` skill（动画丰富，但耗时且风格不可控）与纯手写 HTML（6 页 + 方向键翻页，约 200 行，30 分钟完成）。最终选手写 HTML，内容完全自主，且能投影、也能浏览器直接打开，双用途。

> 返工点：草稿阶段内容密度比视觉炫技重要；skill 适合正式答辩。

## 三、通过证据

- 前端过滤逻辑：`frontend/index.html` 中 `b.date >= todayStr()`，卡片标题为「近期预约（${mine.length}）」；
- POST 3 条今天/未来预约后，三张卡片各显示 1 条；
- 路演 PPT：`docs/路演PPT.html`（6 页，方向键翻页）已就位；
- tag `day9` + 完工报告 issue。

## 四、反思

1. **演示数据的盲区是前端过滤**：API 非空 ≠ 页面有数据，必须走前端渲染确认；
2. **演示数据应进 seed.sql 而非临时 POST**：换库或重置 D1 会消失，应写「相对今天」的动态 seed；
3. **路演 PPT 内容密度优先**：手写 HTML 比 skill 更适合 3 分钟草稿；
4. **PPT 应补失败兜底演示分支**：当前只走 happy path，评委可能问「AI 挂了怎么办」。
