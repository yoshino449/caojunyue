# 对话档案：AI 画架构图漏连线，402 状态码本地线上不一致

> 本文档基于 Day8 反思件还原。

- 日期：2026-10-12
- 场景：Day8 T1 限时冲刺 + T2 文档同步（README 架构图、演示脚本初稿、整改闭环）
- 对话结构：提问 → 排查返工（3 轮）→ 通过

## 一、提问（原话）

> T1 两场限时冲刺（各约 90 分钟）+ T2 文档同步（README 更新含架构图、演示脚本初稿）。

## 二、对话还原

### 第 1 轮：AI 按代码画架构图，人审补虚线

**我**：读 backend / functions / frontend 源码，画一张 Mermaid 架构图。

**AI**：初版准确反映了双轨架构（本地 backend+SQLite / 线上 functions+D1）和 CI 流水线的三个子图，但**漏画了「同代码 / 接口对齐 / SQL 同构」三条虚线关系**——这些跨子图的语义关联，人审才看得出来。

> 返工点：AI 画图在「组件+连线」层面可靠，跨域语义关联仍需人工补充。

### 第 2 轮：演示脚本 vs 实际走查，seed 占坑

**我**：按演示脚本「约→撞→取消→再约」走一遍。

**AI**：浏览器实际走查时，seed 数据已预置了一条投影仪预约**占住目标时段**，步骤 1 直接撞单。脚本只写了 happy path。

> 返工点：演示脚本必须补「前置准备：先取消 seed 预约释放时段」——前置准备是必须项。

### 第 3 轮：402 状态码线上/线下不一致

**我**：IKKO7A issue 正文为空，用自查评审补全。

**AI**：自查发现 `functions/api/bookings/index.js` 对 DeepSeek `402` 返回 `503`，而本地 `ai.js` 把 `402` 映射成 `QUOTA → 429`——同一错误线上/线下状态码不一致，前端提示不准确。

修复（一行）：把该处 `jsonResponse(503, ...)` 改为 `jsonResponse(429, ...)`，与 `backend/server.js` 的 `statusMap`（`QUOTA: 429`）对齐。

> 返工点：本地 `npm test` 5/5 通过，覆盖不到部署适配层的逻辑差异。

## 三、通过证据

- 架构图：双轨 + CI 三子图，人审补上「同代码 / 接口对齐 / SQL 同构」三条虚线；
- `functions/api/bookings/index.js` 的 402 分支改为返回 `429`（`'AI 服务余额不足，请充值后再试'`, `code:'QUOTA'`），与本地一致；
- 互评记录 #4 记录「402 状态码映射不一致」已整改；
- `npm test` 5/5 通过（但覆盖不到 `functions/` 部署适配层）；
- tag `day8` + 完工报告 issue。

## 四、反思

1. **架构图让 AI 画、人审**：组件连线可靠，跨域语义关联需人工补；改路由要同步更图；
2. **演示脚本的「前置准备」是必须项**：seed 占坑会让现场第一步就卡；
3. **状态码映射要跨环境对齐**：仅本地测试不能覆盖部署适配层的逻辑差异；
4. **MCP 配置最后一公里仍需人工**：项目级 `.trae/mcp.json` 被 Trae 标记「模型不可写」（Access denied）。
