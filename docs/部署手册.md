# 部署手册：把教务器材预约部署到 Sealos DevBox

> 写给下届同学：照着一步步来，半小时内拿到一个手机可打开的线上地址。AI 生成 + 人工校对版。
> 为什么用 Sealos：render.com、zeabur.com 国内都打不开；Sealos（cloud.sealos.io，国内容器平台）国内直连。
> 为什么用 DevBox：Sealos「应用管理 → 新建应用」**只接受镜像名**（pre-built image），不接受源码。**源码部署在另一个入口叫「DevBox」**——云端开发环境 + 一键发布为正式应用，不用本地装 Docker。

## 0. 这个项目是什么

一个零 npm 依赖的网页：选器材、选日期时段预约，同一器材同一时段互斥。前端单文件 `frontend/index.html`，后端用 Node 22 内置 `node:sqlite`，启动命令 `node --experimental-sqlite backend/server.js`。**不用装任何 npm 包**。端口走环境变量 `PORT`，启动幂等建库 + seed 自愈。仓库根有 `entrypoint.sh`，DevBox 发布为正式应用时它作为 OCI 镜像入口点。

## 1. 前置检查

- 代码已推到 **Gitee**（自己的仓库 `https://gitee.com/cao-junyue/caojunyue.git`，DevBox 在 WebIDE 里直接 git clone 即可，**不需要 GitHub**）；
- 本地能跑通：
  ```bash
  npm start
  # 打开 http://localhost:3000 看到三张器材卡片 + 统计按钮 + 页脚访问计数
  ```
- 本机**不需要装 Docker**。DevBox 在云端构建，不依赖本地容器环境。

## 2. 在 Sealos DevBox 创建项目

1. 浏览器打开 https://cloud.sealos.io （国内可直连）。
2. 右上注册：手机号或微信扫码登录。**首次使用需实名认证**（国内平台合规要求，上传姓名身份证，几分钟通过）。
3. 新用户有免费赠送额度（具体额度以页面提示为准，够演示一阵子）。
4. 在 Sealos **桌面**找 **DevBox** 图标（一个独立应用，**不是「应用管理」**——应用管理是镜像部署入口，不接受源码）。点开进入 DevBox 项目列表页。
5. 点右上角 **「新建项目」** 按钮，配置如下（按本项目实际值填）：

   | 字段 | 值 / 说明 |
   |---|---|
   | 项目名 | `caojunyue`（自取） |
   | 运行环境 / Runtime | **Node.js**（选 22.x 版本；本项目用 `node:sqlite`，必须 Node ≥ 22。若模板列表只有「Next.js」之类预设，选最接近的 Node 22 通用模板——本项目零 npm 依赖，不用脚手架，直接 git clone 自己的代码覆盖即可） |
   | CPU / 内存 | 滑块拖到 1C/512M 即可演示（官方推荐开发环境 2C4G，演示档够用） |
   | 容器暴露端口 | `3000`（对应代码里 `process.env.PORT \|\| 3000`） |
   | 公网访问 | **开启**（自动分配 `*.sealos.run` 域名；自定义域名可选） |

6. 点右上角 **创建**，等几秒进入 DevBox 项目列表，新项目状态 Running。
7. 操作列选 IDE：**VSCode**（云端 WebIDE，浏览器直开）/ VSCode Insiders / Cursor / Windsurf（后三者本地 IDE 通过 SSH 远程连接）。**最省事选 VSCode**——浏览器直接进 WebIDE，无需本地装任何东西。

## 3. 在 WebIDE 里拉代码并启动

1. WebIDE 自带终端（Terminal → New Terminal），在其中：
   ```bash
   # 拉自己的 Gitee 仓库（DevBox 内网能直连 Gitee）
   git clone https://gitee.com/cao-junyue/caojunyue.git
   cd caojunyue
   ```
2. 确认仓库根有 `entrypoint.sh`（DevBox 发布为正式应用时的启动入口）。其内容就一行：
   ```bash
   node --experimental-sqlite backend/server.js
   ```
   > 注意：DevBox 的 `entrypoint.sh` **只负责启动，不包含构建步骤**。本项目零 npm 依赖，无需 `npm install`。
3. 在 WebIDE 终端里直接试跑：
   ```bash
   # DevBox 注入 PORT 环境变量；本地启动可直接 npm start
   npm start
   ```
   看到 `教务器材预约后端已启动: http://localhost:${PORT}` 即成功。Ctrl+C 停掉。

## 4. 发布版本 + 上线（拿生产域名）

DevBox 的「外网地址」是开发态临时预览，要给教师用必须走「发布版本 → 上线」两步：

1. 回到 DevBox 项目列表，点你项目的 **「详情」**，进项目详情页。
2. 找 **「版本历史」** 区域，点右上角 **「发布版本」** 按钮。
3. 在弹窗填：
   - **镜像名**：默认预填项目名，保持即可
   - **版本号**：`v1.0`
   - **版本描述**：`初始版本`（自取）
4. 点 **「发版」**，等几十秒到一两分钟，系统把当前代码 + `entrypoint.sh` 打成标准 OCI 镜像。完成后「版本历史」里出现该版本记录。
5. 在该版本的操作栏点 **「上线」**，系统跳转到 Sealos「应用管理」（这里镜像已由 DevBox 准备好，不需要你手动 build/push）。
6. 在应用管理部署向导配置：
   - 应用名：`caojunyue`
   - CPU/内存：1C/512M 即可
   - 实例数：1
   - 外网访问：**开启**（拿公网域名）
7. 点右上角 **「部署应用」**，等状态变 Running。
8. 进应用详情页，点 **「公网地址」**——这就是教师手机要打开的 `*.sealos.run` 域名。

## 5. 验收

- **教师手机**打开 `https://你的域名` → 应看到：三张器材卡片（各含 2 条示例预约 seed 数据）、页脚「本页已被访问 N 次」、右上角「📊 统计」按钮可点出图表。
- 打开 `https://你的域名/ping` → 返回 `ok`（健康检查通过）。
- 多刷几次首页 → 页脚访问计数应递增。

## 6. 坑在哪（提前避雷）

1. **应用管理不接受源码**：「应用管理 → 新建应用」只接受镜像名（pre-built image），没有「从源码构建」选项。**源码部署走 DevBox**，这是另一个入口，别走错。
2. **Start 必须带 `--experimental-sqlite`**。`entrypoint.sh` 已写好，别手改成 `node backend/server.js`，否则 `node:sqlite` 报错启动失败。
3. **Node 版本必须 22+**。创建 DevBox 时 Runtime 选 22.x；选成 18/20 会报 `Cannot find module 'node:sqlite'`。
4. **端口要 3000 且开启外网访问**：DevBox 项目端口填 3000、外网访问开关打开，否则拿不到域名。
5. **监听地址需为 0.0.0.0**：Node 原生 `http` 默认监听所有网卡，满足要求；不要手改成 `127.0.0.1`，否则外网访问不到。
6. **容器文件系统不持久**：DevBox 发布的应用重启会清空 `data/` 目录，但启动时 `ensureDb()` 自动建表 + 写 seed，所以页面永远不会是空的——预约数据回到 2 条示例、访问计数归零。**这是已知限制，不是 bug**。要持久化得挂持久卷（DevBox 支持「持久存储」挂载到 `/app/data`），超出本章范围。
7. **实名认证**：国内平台合规要求，不实名用不了；几分钟搞定别跳过。

## 7. 日常更新

本地改完代码 → `git push` 到 Gitee main → 进 DevBox WebIDE 终端 `git pull` → 回 DevBox 项目详情页 **「版本历史」** → **「发布版本」**（填新版本号如 `v1.1`）→ **「发版」** → 新版本点 **「上线」** 重建应用（公网域名不变，容器重建后数据清回 seed）。

## 附录 A：备选路径——应用管理 + 镜像部署（不用 DevBox）

如果你已经有打好的 OCI 镜像（比如本地用 `Dockerfile` 构建并推到了镜像仓库），可以走「应用管理 → 新建应用」：

1. 仓库根有 [`Dockerfile`](../Dockerfile)（`FROM node:22-slim` + `--experimental-sqlite` + EXPOSE 3000）；
2. 本地装 Docker 后构建并推到镜像仓库（如 docker.io、阿里云 ACR）：
   ```bash
   docker build -t 你的用户名/caojunyue .
   docker push 你的用户名/caojunyue
   ```
3. cloud.sealos.io → 应用管理 → 新建应用 → 镜像名填 `你的用户名/caojunyue`，端口 3000，开外网访问。

> 本路径需要本机装 Docker + 镜像仓库账号，比 DevBox 麻烦。**T2 验收推荐 DevBox**，应用管理仅作备选。

## 附录 B：把 Gitee 仓库镜像到 GitHub（仅 Sealos 应用管理 / Render / Zeabur 需要）

DevBox 在 WebIDE 里直接 git clone Gitee 即可，**不需要镜像到 GitHub**。只有走「应用管理 + 镜像」路径、或换 Render/Zeabur 时才需要 GitHub。Gitee 仓库搬到 GitHub 两种方法：

**方法 1（最省事，不敲命令）— GitHub Import：**
1. 登录 GitHub，访问 https://github.com/new/import
2. **Your old repository's clone URL** 填 Gitee 地址：`https://gitee.com/cao-junyue/caojunyue.git`
3. **Repository name** 填 `caojunyue`
4. 点 **Begin import**，等几秒到几十秒，GitHub 给你一个 `https://github.com/你的用户名/caojunyue`，代码全在。

**方法 2（双 remote，两边都推）：**
```bash
# 在 e:\Desktop\vibe-lab1 下
git remote add github https://github.com/你的用户名/caojunyue.git
git push -u github main
# 以后：git push origin main 推 Gitee；git push github main 推 GitHub
```
