# 部署手册：把教务器材预约部署到 Sealos

> 写给下届同学：照着一步步来，半小时内拿到一个手机可打开的线上地址。AI 生成 + 人工校对版。
> 为什么用 Sealos：render.com、zeabur.com 国内都打不开；Sealos（国内容器平台 cloud.sealos.io）国内直连。代码不改，加一个 Dockerfile 容器化即可。

## 0. 这个项目是什么

一个零 npm 依赖的网页：选器材、选日期时段预约，同一器材同一时段互斥。前端单文件 `frontend/index.html`，后端用 Node 22 内置 `node:sqlite`，启动命令 `node --experimental-sqlite backend/server.js`。**不用装任何 npm 包**。端口走环境变量 `PORT`，启动幂等建库+seed 自愈。仓库根有 `Dockerfile`，容器平台一键构建。

## 1. 前置检查

- 本机已装 Node.js ≥ 22（命令行 `node -v` 看版本）；
- 代码已推到 **GitHub**（Sealos 源码构建读 GitHub；Gitee 仓库先镜像到 GitHub，见附录 A）；
- 本地能跑通：
  ```bash
  npm start
  # 打开 http://localhost:3000 看到三张器材卡片 + 统计按钮 + 页脚访问计数
  ```
- （可选，想本地验证容器）本机装了 Docker：`docker build -t caojunyue . && docker run -p 3000:3000 caojunyue`。

## 2. 在 Sealos 上创建应用

1. 浏览器打开 https://cloud.sealos.io （国内可直连）。
2. 右上注册：手机号或微信扫码登录。**首次使用需实名认证**（国内平台合规要求，上传姓名身份证，几分钟通过）。
3. 新用户有免费赠送额度（具体额度以页面提示为准，够演示一阵子）。
4. 进控制台，找 **「应用管理」**（或「应用开发」/「我的应用」，UI 会随版本微调）→ **「新建应用」**。
5. 选择 **「从源码构建」** / **「GitHub」** 方式：
   - 仓库地址填：`https://github.com/你的用户名/caojunyue`（GitHub 镜像见附录 A）
   - 分支：`main`
   - Sealos 会检测到仓库根的 `Dockerfile`，自动用它构建镜像（无需你手填构建命令）。
6. 配置服务：

   | 项 | 值 / 说明 |
   |---|---|
   | 容器端口 | `3000`（Dockerfile 里 EXPOSE 3000，对应代码读的 `PORT`） |
   | CPU / 内存 | 默认最小档即可（演示用） |
   | 副本数 | 1 |
   | 是否外网访问 | **开启**（不开启就拿不到域名） |

7. 点 **部署**，等构建 + 拉起容器，状态变 Running。

## 3. 拿域名

1. 部署成功后，应用详情页找 **「外网访问」** / **「域名」**。
2. Sealos 会分配一个 `*.sealos.io`（或 `*.sealos.cn`）的子域名，点开即访问。

## 4. 验收

- **教师手机**打开 `https://你的域名` → 应看到：三张器材卡片（各含 2 条示例预约 seed 数据）、页脚「本页已被访问 N 次」、右上角「📊 统计」按钮可点出图表。
- 打开 `https://你的域名/ping` → 返回 `ok`（健康检查通过）。
- 多刷几次首页 → 页脚访问计数应递增。

## 5. 坑在哪（提前避雷）

1. **Start 必须带 `--experimental-sqlite`**。Dockerfile 的 `CMD` 已写好，别手改成 `node backend/server.js`，否则 `node:sqlite` 报错启动失败。
2. **Node 版本必须 22+**。Dockerfile 用 `node:22-slim`。如果 Sealos 构建日志看到 `Cannot find module 'node:sqlite'`，就是基础镜像版本错了，确认 Dockerfile 第 3 行是 `FROM node:22-slim`。
3. **基础镜像拉不下来**：`node:22-slim` 默认从 Docker Hub 拉，国内偶尔慢/失败。若构建卡在拉镜像，把 Dockerfile 第 3 行改成国内镜像源，如 `FROM docker.m.daocloud.io/library/node:22-slim`（DaoCloud 镜像）或 `FROM registry.cn-hangzhou.aliyuncs.com/library/node:22-slim`（阿里云镜像）。
4. **端口要 3000 且开启外网访问**：容器端口填 3000、外网访问开关打开，否则拿不到域名。
5. **容器文件系统不持久**：Sealos 容器重启会清空 `data/` 目录，但启动时 `ensureDb()` 自动建表 + 写 seed，所以页面永远不会是空的——预约数据回到 2 条示例、访问计数归零。**这是已知限制，不是 bug**。要持久化得挂持久卷（Sealos 支持「持久存储」挂载到 `/app/data`），超出本章范围。
6. **实名认证**：国内平台合规要求，不实名用不了；几分钟搞定别跳过。
7. **Sealos 连 GitHub 不连 Gitee**：源码构建一般要 GitHub 地址。Gitee 仓库镜像到 GitHub 的方法见附录 A。

## 6. 日常更新

本地改完代码 → `git push` 到 GitHub → Sealos 检测到新提交自动重新构建部署（域名不变，容器重建后数据清回 seed）。

## 附录 A：把 Gitee 仓库镜像到 GitHub

Sealos 源码构建一般连 GitHub。Gitee 仓库搬到 GitHub 两种方法：

**方法 1（最省事，不敲命令）— GitHub Import：**
1. 登录 GitHub，访问 https://github.com/new/import
2. **Your old repository's clone URL** 填 Gitee 地址：`https://gitee.com/cao-junyue/caojunyue.git`
3. **Repository name** 填 `caojunyue`
4. 点 **Begin import**，等几秒到几十秒，GitHub 给你一个 `https://github.com/你的用户名/caojunyue`，代码全在。

**方法 2（双 remote，两边都推）：**
```bash
# 在 e:\Desktop\vibe-lab1 下
git remote add github https://github.com/你的用户名/caojunyue.git
git push -u github main
# 以后：git push origin main 推 Gitee；git push github main 推 GitHub
```

## 附录 B：其他平台（需梯子，国内打不开）

- **Zeabur**（`*.zeabur.app`）与 **Render**（`*.onrender.com`）运行时模型与 Sealos 一致（Node web service + 注入 `PORT` + 可写文件系统），代码与 Dockerfile 都不改即可用。仓库根 `render.yaml` 留作 Render 备选声明式配置。能用梯子时再试这两个。
