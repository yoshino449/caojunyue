# 部署手册：把教务器材预约部署到 Render

> 写给下届同学：照着一步步来，半小时内拿到一个手机可打开的线上地址。AI 生成 + 人工校对版。
> 为什么换平台：之前用 Sealos DevBox，但 Sealos 改版后实际页面与本手册旧版教程差距大、登录与创建项目环节卡住过不去；改用 Render（render.com，国内可直连、Free 计划 $0/月、登录方式简单、流程最稳定）。
> 为什么选 Render：① 国内可直连（实测 render.com、dashboard.render.com、render.com/docs 均可正常打开）；② Free 计划 $0/月、750 小时/月够单实例 24×7 跑满；③ 仓库已有 `render.yaml` 声明式配置 + Node 默认 24（满足 `node:sqlite` 所需 ≥22）+ `process.env.PORT` 已适配，**代码一行不改**。

## 0. 这个项目是什么

一个零 npm 依赖的网页：选器材、选日期时段预约，同一器材同一时段互斥。前端单文件 `frontend/index.html`，后端用 Node 22 内置 `node:sqlite`，启动命令 `node --experimental-sqlite backend/server.js`。**不用装任何 npm 包**。端口走环境变量 `PORT`（Render 默认注入 10000），启动幂等建库 + seed 自愈。

## 1. 前置准备

需要两样东西：**GitHub 账号** + **代码在 GitHub**（Render 不连 Gitee）。

### 1.1 注册 GitHub 账号（已有跳过）

浏览器打开 https://github.com/signup ，邮箱注册（国内邮箱可注册，无需梯子，加载稍慢但能进）。

### 1.2 把 Gitee 仓库镜像到 GitHub

Render 只接 GitHub/GitLab/Bitbucket，不接 Gitee。把仓库搬一份到 GitHub（不影响 Gitee，两边都能继续推）：

**方法 1（最省事，不敲命令）— GitHub Import：**

1. 登录 GitHub，访问 https://github.com/new/import
2. **Your old repository's clone URL** 填 Gitee 地址：`https://gitee.com/cao-junyue/caojunyue.git`
3. **Repository name** 填 `caojunyue`
4. 点 **Begin import**，等几秒到几十秒，GitHub 给你一个 `https://github.com/你的用户名/caojunyue`，代码全在。

**方法 2（双 remote，以后两边都推）：**

```bash
# 在 e:\Desktop\vibe-lab1 下
git remote add github https://github.com/你的用户名/caojunyue.git
git push -u github main
# 以后：git push origin main 推 Gitee；git push github main 推 GitHub
```

### 1.3 本地自检（可选但推荐）

```bash
npm start
# 打开 http://localhost:3000 看到三张器材卡片 + 统计按钮 + 页脚访问计数
```

本机不需要装 Docker，Render 在云端构建。

## 2. 注册 Render 账号

1. 浏览器打开 https://dashboard.render.com/register （国内可直连）。
2. 注册方式三选一：
   - **用 GitHub 注册**（推荐，下一步要连 GitHub，最省事）；
   - 用 Google 注册；
   - 用邮箱 + 密码注册。
3. 注册后进 https://dashboard.render.com 控制台首页。

> 没有实名认证环节，没有手机号验证，比国内平台省事。

## 3. 创建 Web Service

1. 控制台首页点右上角 **New** → **Web Service**：

   ![New Web Service](https://aka.doubaocdn.com/s/WjbKtUV2zb)

2. 选 **Git Provider**（连接 Git 提供商）：

   - 第一次会让你授权 Render 访问 GitHub 账号；
   - 推荐选 **「仅授权特定仓库」**（更安全），勾选你的 `caojunyue` 仓库；
   - 授权后回到 Render，仓库列表里出现 `你的用户名/caojunyue`，点 **Connect**。

3. 进入服务创建表单，按下表填（项目实际值）：

   | 字段 | 值 / 说明 |
   |---|---|
   | **Name** | `caojunyue`（自取，会拼进域名 `caojunyue.onrender.com`） |
   | **Region** | 选离你最近的（国内选 Singapore 或 Hong Kong，没有 Hong Kong 选 Singapore） |
   | **Branch** | `main` |
   | **Root Directory** | 留空（仓库根就是项目根） |
   | **Runtime** | 选 **Node**（默认会装 Node 24，满足 ≥22 要求） |
   | **Build Command** | 留空（零 npm 依赖，无需 install）。如果 Render 不让留空，填 `npm install` 也无妨（package.json 无 dependencies 会跳过） |
   | **Start Command** | `node --experimental-sqlite backend/server.js`（**必须带 `--experimental-sqlite`，否则 `node:sqlite` 报错**） |

4. 选 **Instance Type** = **Free**（$0/月，750 小时/月够 24×7 跑满单实例）：

   ![Free plan](https://aka.doubaocdn.com/s/s8LAJpSF8F)

5. 展开 **Advanced** 折叠区，按下表设置（关键，影响健康检查与自动重启判断）：

   | 字段 | 值 |
   |---|---|
   | **Health Check Path** | `/ping`（仓库 `server.js` 已实现 `GET /ping` 返回 `ok`） |
   | **Health Check Grace Period** | `60` 秒（Node 启动 + `ensureDb()` 建库需要几秒，给足时间避免误判失败） |
   | **Auto-Deploy** | 勾选（push 到 main 自动重新部署） |

6. 检查无误后点页面底部 **Create Web Service**。

7. 跳转到服务详情页，自动开始第一次构建 + 部署。等 1~3 分钟，状态从 **Building** → **Deploying** → **Live**。

8. 部署成功后页面顶部出现公网地址：`https://caojunyue.onrender.com`（按你的服务名拼）——这就是教师手机要打开的域名。

## 4. 验收

打开你的域名自检 + 教师手机验收：

| 检查项 | 通过标准 |
|---|---|
| 首页 `https://你的域名/` | 三张器材卡片（投影仪 / 单反相机 / 便携音响）+ 页脚「本页已被访问 N 次」+ 右上角「📊 统计」按钮 |
| 健康检查 `https://你的域名/ping` | 返回 `ok`（裸字符串，不是 JSON） |
| 预约列表 `https://你的域名/api/bookings` | 返回 JSON 数组（含 2 条 seed 示例数据） |
| 访问统计 `https://你的域名/api/visits` | 返回 `{"count":N}`，刷新首页 N 递增 |
| 预约统计 `https://你的域名/api/stats` | 返回 `perEquip` 与 `perSlot` 两条聚合数组 |
| 点「📊 统计」按钮 | 弹出柱状图（各器材预约量）+ 饼图（各时段热度） |
| 教师手机 4G 打开 | 首页可正常显示与交互（首次打开可能慢 30~60 秒，见下文「Free 层 spin down」坑） |

## 5. 坑在哪（提前避雷）

1. **必须带 `--experimental-sqlite`**：Start Command 写成 `node backend/server.js` 会在第一次预约时抛 `Cannot find module 'node:sqlite'`。Render 控制台 → 服务 → Settings → Start Command 改回 `node --experimental-sqlite backend/server.js` 后 Manual Deploy 即可。
2. **Free 层 15 分钟 spin down**：Free 计划的 web service **15 分钟无请求会休眠**，下次访问需 30~60 秒冷启动唤醒，期间浏览器显示 Render 加载页。这是免费层已知限制，不是 bug。**对策**：① 教师验收前自己先访问一次预热；或 ② 升级到 Starter（$7/月）取消休眠。
3. **重启清库（ephemeral 文件系统）**：每次重新部署 / 重启 / spin down 唤醒，`data/equipment.db` 文件会丢失。但 `server.js` 启动调 `ensureDb()` 幂等建表 + seed 自愈，所以页面永远不会空——预约数据回 2 条示例、**访问计数归零**。**已知限制，不修**（持久化需付费挂持久卷，超出 T2 范围）。
4. **Node 版本默认 24**：Render Node runtime 默认 24.21.0，满足 `node:sqlite` 所需 ≥22。如需固定版本，在服务 Environment 里加环境变量 `NODE_VERSION=22`（或仓库根加 `.node-version` 文件，内容就一行 `22`）。
5. **PORT 走环境变量**：Render 默认注入 `PORT=10000`，`server.js` 已 `const PORT = process.env.PORT || 3000` 适配。**不要硬编码 3000**，否则 Render 检测不到端口绑定、部署失败。
6. **监听 0.0.0.0**：Node 原生 `http.createServer().listen(PORT)` 默认监听所有网卡，满足 Render 公网转发要求。**不要手改成 `127.0.0.1`**，否则外网访问不到。
7. **Build Command 留空还是 `npm install`**：本项目 `package.json` 无 `dependencies`，Render 会跳过 install。留空最干净；若 Render 强制非空，填 `npm install` 也无副作用。
8. **GitHub 仓库必须最新**：本地改完代码 → `git push origin main` 推 Gitee → `git push github main` 同步 GitHub → Render 检测到 push 自动重新部署（开了 Auto-Deploy 的话）。**两边都要推**，别只推 Gitee。
9. **首次部署可能失败一次**：如果第一次部署卡在 Building 阶段几分钟无进展，多半是 Render 在拉镜像或冷启动构建节点，再等一两分钟；超 5 分钟看 Logs（服务详情页 → Logs 标签），常见原因就是 Start Command 漏了 `--experimental-sqlite`。

## 6. 日常更新流程

本地改完代码 → `git push origin main` 推 Gitee → `git push github main` 同步 GitHub → Render 检测到 main 分支 push → 自动触发重新构建部署（开了 Auto-Deploy 的话，1~3 分钟后线上是新版）。**域名不变，容器重建后数据清回 seed**。

也可在 Render 控制台手动触发：服务详情页 → 右上角 **Manual Deploy** → **Deploy latest commit**。

## 附录 A：用 `render.yaml` 一键配置（Blueprint）

仓库根已有 [`render.yaml`](../render.yaml)，是 Render 的声明式配置（Infrastructure-as-Code）。如果你不想手填表单，可以这样：

1. 控制台首页点 **New** → **Blueprint**（不是 Web Service）。
2. 选 Git Provider → 连接 GitHub → 选 `caojunyue` 仓库。
3. Render 自动检测到仓库根的 `render.yaml`，按其内容创建服务（type/name/runtime/branch/plan/startCommand/healthCheckPath/autoDeploy 全部声明在内），无需手填。
4. 点 **Apply**，等部署完成拿域名。

`render.yaml` 内容（已就位，无需改）：

```yaml
services:
  - type: web
    name: caojunyue
    runtime: node
    branch: main
    plan: free
    buildCommand: ""        # 零 npm 依赖，无需 install
    startCommand: "node --experimental-sqlite backend/server.js"
    healthCheckPath: /ping
    autoDeploy: true
```

> Blueprint 路径与手动路径效果一致，区别只是省去手填表单的步骤。**第一次部署推荐手动路径**，能看到每一步实际值，便于排错；稳定后想重新部署可改用 Blueprint。

## 附录 B：用 Dockerfile 部署到 Render（绕过 Node runtime）

仓库根已有 [`Dockerfile`](../Dockerfile)（`FROM node:22-slim` + `--experimental-sqlite` + EXPOSE 3000）。如果担心 Render Node runtime 版本兼容性，可改用 Docker runtime：

1. 控制台 **New** → **Web Service** → 选 GitHub 仓库。
2. **Runtime** 不选 Node，选 **Docker**。
3. Render 自动读取仓库根 `Dockerfile` 构建。
4. 其余字段（Name / Region / Branch / Free 计划）同主流程。
5. **Health Check Path** 仍填 `/ping`。

> Docker 路径与 Node runtime 路径效果一致，构建稍慢（多一层 Docker build）。**除非遇到 Node runtime 报怪错，否则不推荐**，主流程已验证可用。
