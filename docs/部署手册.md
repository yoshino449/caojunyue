# 部署手册：把教务器材预约部署到 Zeabur

> 写给下届同学：照着一步步来，半小时内拿到一个手机可打开的线上地址。AI 生成 + 人工校对版。
> 为什么用 Zeabur 不用 Render：render.com 在国内基本打不开；Zeabur（亚洲团队、`*.zeabur.app` 域名）国内可直连。代码一行都不用改，两个平台运行时模型一致。

## 0. 这个项目是什么

一个零 npm 依赖的网页：选器材、选日期时段预约，同一器材同一时段互斥。前端单文件 `frontend/index.html`，后端用 Node 22 内置 `node:sqlite`，启动命令 `node --experimental-sqlite backend/server.js`。**不用装任何 npm 包**。端口走环境变量 `PORT`，启动幂等建库+seed 自愈。

## 1. 前置检查

- 本机已装 Node.js ≥ 22（命令行 `node -v` 看版本）；
- 代码已推到 **GitHub**（Zeabur 连 GitHub，不连 Gitee；Gitee 仓库可用 GitHub 的 Import 功能一键镜像过去，见附录）；
- 本地能跑通：
  ```bash
  npm start
  # 打开 http://localhost:3000 看到三张器材卡片 + 统计按钮 + 页脚访问计数
  ```

## 2. 在 Zeabur 上创建服务

1. 浏览器打开 https://zeabur.com （国内可直连，不用梯子）。
2. 右上 **Login** → 用 **GitHub 账号登录**（最顺，后面连仓库直接用）；没有 GitHub 账号就先注册一个。
3. 登录后选 **New Project**，起个名（如 `caojunyue`），确认。
4. 进项目页，点 **Add Service** → **Git Repository** → 选 **GitHub**。
5. 第一次会让你授权 Zeabur 访问 GitHub：选 **Only select repositories**，只勾 `caojunyue` 这一个仓库，授权。
6. 列表里选 `caojunyue`，分支 `main`。
7. Zeabur 会自动识别 `package.json` 并按以下方式跑（一般不用改，确认即可）：

   | 项 | 值 / 说明 |
   |---|---|
   | Build Command | 留空或自动（零 npm 依赖，几乎瞬间完成） |
   | Start Command | `npm start`（即 `node --experimental-sqlite backend/server.js`） |
   | 端口 | 自动读 `PORT` 环境变量（代码已支持 `process.env.PORT \|\| 3000`） |
   | Plan | Free / Developer（免费档，有用量上限够演示用） |

8. 等 1–2 分钟，服务状态变绿（Running）即部署成功。

## 3. 绑域名

1. 服务页找 **Networking**（或 **Domains**）标签。
2. 点 **Generate Domain**（或 Add Domain → zeabur.app）。
3. Zeabur 给你一个 `*.zeabur.app` 子域名，如 `caojunyue.zeabur.app`。

## 4. 验收

- **教师手机**打开 `https://你的域名.zeabur.app` → 应看到：三张器材卡片（各含 2 条示例预约 seed 数据）、页脚「本页已被访问 N 次」、右上角「📊 统计」按钮可点出图表。
- 打开 `https://你的域名.zeabur.app/ping` → 返回 `ok`（健康检查通过）。
- 多刷几次首页 → 页脚访问计数应递增。

## 5. 坑在哪（提前避雷）

1. **Start Command 必须带 `--experimental-sqlite`**。少了这个标志，`node:sqlite` 在 Node 22 里是实验性的、会直接报错启动失败。`package.json` 的 `start` 脚本已写好，Zeabur 自动用 `npm start`，别手改成 `node backend/server.js`。
2. **Node 版本必须是 22+**。Zeabur 一般会按 `package.json` 里的 `"engines": {"node": ">=22"}` 自动选。如果部署日志看到 `Cannot find module 'node:sqlite'`，就是版本低了，去服务设置里把 Node 版本调到 22。
3. **端口不能写死 3000**。Zeabur 注入 `PORT` 环境变量，代码里已改成 `process.env.PORT || 3000`。别改回硬编码。
4. **GitHub 授权范围**：装 Zeabur GitHub App 时选「只授权 `caojunyue`」更安全。
5. **免费档会休眠/有用量上限**：Zeabur 免费档有用量或休眠策略，长时间不访问可能停服，下次访问冷启动十几秒；重启可能清空运行时数据。但服务启动时 `ensureDb()` 会自动建表 + 写 seed 示例，所以页面永远不会是空的——预约数据回到 2 条示例、访问计数归零。**这是免费档已知限制，不是 bug**。要持久化得开付费卷，超出本章范围。
6. **Gitee → GitHub 镜像**：Zeabur 连不了 Gitee，必须用 GitHub。Gitee 仓库搬到 GitHub 的方法见下方附录。

## 6. 日常更新

本地改完代码 → `git push` 到 GitHub（如果配了双 remote 也推 Gitee）→ Zeabur 检测到新提交自动重新部署（地址不变，运行时数据会被清回 seed）。

## 附录 A：把 Gitee 仓库镜像到 GitHub（Zeabur 要连 GitHub）

Zeabur 和 Render 都只连 GitHub/GitLab，不连 Gitee。两种搬法：

**方法 1（最省事，不敲命令）— GitHub Import：**
1. 登录 GitHub，访问 https://github.com/new/import
2. **Your old repository's clone URL** 填 Gitee 地址：`https://gitee.com/cao-junyue/caojunyue.git`
3. **Repository name** 填 `caojunyue`
4. 点 **Begin import**，等几秒到几十秒，GitHub 给你一个 `https://github.com/你的用户名/caojunyue`，代码全在。

**方法 2（双 remote，两边都推）：**
```bash
# 在 e:\Desktop\vibe-lab1 下
git remote add github https://github.com/你的用户名/caojunyue.git
git push -u github main
# 以后：git push origin main 推 Gitee；git push github main 推 GitHub
```

## 附录 B：如果非要用 Render（需要梯子）

render.com 国内打不开，能用梯子的话也可部署，仓库根有现成的 `render.yaml`（声明式配置）。字段：Runtime Node、Branch main、Build 留空、Start `node --experimental-sqlite backend/server.js`、Plan Free、Health Check `/ping`。其余坑点同上。
