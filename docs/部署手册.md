# 部署手册：把教务器材预约部署到 Render 免费层

> 写给下届同学：照着一步步来，半小时内你能拿到一个手机可打开的线上地址。AI 生成 + 人工校对版。

## 0. 这个项目是什么

一个零 npm 依赖的网页：选器材、选日期时段预约，同一器材同一时段互斥。前端单文件 `frontend/index.html`，后端用 Node 22 内置 `node:sqlite`，启动命令 `node --experimental-sqlite backend/server.js`。**不用装任何 npm 包**。

## 1. 前置检查

- 本机已装 Node.js ≥ 22（命令行 `node -v` 看版本）；
- 代码已推到 Gitee 仓库（公开仓库，Render 要能拉取）；
- 本地能跑通：
  ```bash
  npm start
  # 打开 http://localhost:3000 看到三张器材卡片 + 统计按钮 + 页脚访问计数
  ```

## 2. 在 Render 上创建服务

1. 注册 Render：打开 https://render.com ，用 GitHub 或 Gitee 账号登录（Gitee 登录需先在 Render 绑定 Gitee 账号授权）。
2. 点 **New +** → **Web Service**。
3. 选 **Build and deploy from a Git repository** → 连接你的 Gitee 仓库 `caojunyue`。
4. 填配置（关键字段，与仓库 `render.yaml` 一致）：

   | 字段 | 填什么 |
   |---|---|
   | Name | `caojunyue`（任意，会决定子域名） |
   | Runtime | **Node** |
   | Branch | `main` |
   | Build Command | 留空（零依赖，无需 `npm install`） |
   | Start Command | `node --experimental-sqlite backend/server.js` |
   | Plan | **Free** |
   | Health Check Path | `/ping` |

5. 点 **Create Web Service**，等首次部署（会拉代码、跑 Start Command，约 1–2 分钟）。

## 3. 验收

部署成功后 Render 会给你一个地址，形如 `https://caojunyue.onrender.com`。

- 用**教师手机**打开这个地址 → 应看到：三张器材卡片、每张含 2 条示例预约（seed 数据）、页脚显示「本页已被访问 N 次」、右上角「📊 统计」按钮可点出图表。
- 打开 `https://你的地址/ping` → 返回 `ok`（健康检查通过）。
- 多刷几次首页 → 页脚访问计数应递增。

## 4. 坑在哪（提前避雷）

1. **Start Command 必须带 `--experimental-sqlite`**。少了这个标志，`node:sqlite` 在 Node 22 里是实验性的、会直接报错启动失败。仓库 `package.json` 的 `start` 脚本和 `render.yaml` 都已写好，照抄即可。
2. **Node 版本必须是 22+**。Render 默认 Node 版本可能不是 22，靠 `package.json` 里的 `"engines": {"node": ">=22"}` 让 Render 自动选 22。如果部署日志里看到 `Cannot find module 'node:sqlite'`，就是版本低了。
3. **端口不能写死 3000**。Render 会用环境变量 `PORT` 注入一个随机端口，代码里已经改成 `process.env.PORT || 3000`。别改回硬编码。
4. **免费层会休眠 + 清库**。Render 免费层 15 分钟无访问会自动休眠，下次访问冷启动约 30 秒；重启会清空 `data/` 目录。但服务启动时会自动建表 + 写入 seed 示例数据（`ensureDb()` 幂等），所以页面永远不会是空的——预约数据回到 2 条示例、访问计数归零。**这是免费层已知限制，不是 bug**。要持久化得开付费的 Persistent Disk，超出本章范围。
5. **健康检查路径填 `/ping`**。填错或漏填，Render 可能判服务不健康反复重启。
6. **Gitee 连接授权**。Render 对 Gitee 的连接有时需要你在 Gitee 的「设置 → 第三方应用」里先授权给 Render，否则拉不到代码。

## 5. 日常更新

本地改完代码 → `git push` → 在 Render 的服务页点 **Manual Deploy** 或等自动部署（`render.yaml` 里 `autoDeploy: true`）。部署完地址不变，数据因 ephemeral 会被清回 seed。

## 6. 想要持久化（进阶，可选）

如果想让预约数据和访问计数跨重启保留，二选一：
- Render 服务配置里加一个 **Disk**（付费，挂载到 `data/` 目录），`data/equipment.db` 就持久了；
- 或把 SQLite 换成云数据库（如 Turso、Supabase），改造 `backend/db.js` 的连接层——但这会引入第三方驱动，需先在 AGENTS.md 与技术方案更新技术栈约束。

> 本章不做这两件事，保持零依赖。手册到此为止。
