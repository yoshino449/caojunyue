01部署平台演进

问题

Sealos / Render 免费层不可用

Sealos cloud.sealos.io 改版后创建项目流程与教程差距大、登录卡死；Render 免费层 15 分钟无请求休眠，重启清库——预约数据回 seed、访问计数归零。

解决

改用 Cloudflare Pages + Functions + D1

pages.dev 国内可直连、Free $0/月、无信用卡、边缘运行无休眠、D1 数据库持久化不丢。新增 functions/ 子树（ESM）+ wrangler.toml D1 binding。

结果：5 个验收 URL 全通过，教师手机可开，数据不丢。

02换个设备就撞单？

问题

v1 只在自己浏览器里记

同学 A 在电脑上约了投影仪，同学 B 手机打开页面——电脑记的事手机看不到，B 又约了同一时段，撞单了！

解决

把"不能撞"钉死在数据库

预约规则从浏览器搬到服务器：任何设备来约，服务器先查数据库——有冲突直接拒，前端只管提交不管判。

结果：跨设备再也撞不了单，前端那套旧逻辑直接废掉。

03CI 流水线按文档写的跑不起来

问题

Gitee Go 处处是"默认"

按教程写的配置格式不对、分支对不上、自带的 Node 版本太低跑不了我们的代码——推上去全红。

解决

照它的脾气改，装它没有的

按 Gitee Go 的格式重写配置、双分支同步、流水线里先装 Node 22 再跑测试——现在 push 自动验。

结果：push → 自动装依赖 → 自动跑测试全绿，故意写错能拦住。

04本地跑通，线上报错不一样

问题

AI 助手失败了，用户看到两副面孔

本地调 AI 额度用尽 → 提示"请稍后再试"，线上同样情况 → 提示"服务不可用"，同一个问题说两种话，用户懵了。

解决

对齐两端的错误码

把线上和本地的错误提示统一映射，不管在哪跑、怎么跑，用户看到的提示永远一致。

结果：本地与线上同代码同行为，AI 助手兜底提示完全一致。

05总结：5 个坑，5 个闭环

踩过的坑

从部署到测试，处处是"默认"

  • 换个设备就撞单——规则写在了浏览器里
  • 按教程配的 CI 跑不起来
  • 本地和线上同一个问题说两种话
  • 测试连跑三次全挂，业务代码一行没改
我们改了什么

只动必须动的，不碰已经对的

  • 把"不能撞"钉死在数据库
  • 照 Gitee Go 的脾气重写配置
  • 统一两端的错误提示
  • 测试脚本自己修，业务代码零改动
