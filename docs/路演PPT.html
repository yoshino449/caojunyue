功能列表 · AC 清单

F1 浏览器材

三张卡片：投影仪 / 单反 / 音响，展示今天起预约。

F2 提交预约

预约人 + 日期 + 五选一时段；成功后立即出现在卡片。

F3 时段互斥

同器材+同日+同时段仅一条；重复在弹窗内红字拒绝。

F4 取消释放

二次确认删除，时段立即释放可被他人重约。

F5 统计图表

Chart.js 柱状图（各器材预约量）+ 饼图（各时段热度）。

F6 AI 助手

DeepSeek 自然语言查预约，Key 存服务端，失败有兜底。

现场真的能跑

  • 双轨架构：本地 backend/（CommonJS + node:sqlite）↔ 线上 functions/（ESM + D1 binding），前端同代码无需切换
  • 互斥兜底：数据库唯一索引 UNIQUE(equip_id, date, slot)，服务端 409，前端不本地判重
  • 5 条测试：node:test 零依赖，同键409 / 换时段201 / 换器材201 / 过去日期400 / 取消释放再约201，全绿
  • CI：Gitee Go，push master → 装依赖 → 跑测试，构建历史页可查
  • 线上：Cloudflare Pages 边缘运行 + D1 持久化，无休眠、数据不丢

线上 5 个验收 URL 全通过：/ping /api/ping /api/bookings /api/visits /

我怎么指挥 AI

我把 PRD 三件套（需求/技术方案/任务看板）当 AI 的唯一上下文：每条功能线按"任务卡→@相关文件→AI 实现→本地跑→diff 审→commit"循环，AI 写代码我审 diff，跑挂了先改用例不改业务。互斥判重从 localStorage 前端判重迁到服务端唯一索引，是 AI 按技术方案 §11 重构的；CI 踩坑、D1 状态码不一致、Cloudflare Functions 命名限制，全部靠"先收集证据再最小修复"闭环。我指挥方向与验收，AI 出手速与覆盖面。
